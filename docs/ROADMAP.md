# dshed Roadmap（讨论稿 v0.1）

> 状态：讨论稿，待与 Codex 评审后定稿。本文档是战略规划，不是交付承诺。

## 0. 定位

**一句话**：dshed 是 dsh（DeepSeek Harness）的"发行版"——把引擎变成开箱即用的行业 Agent 桌面。

**为什么**：
- dsh 是基建（引擎），它的价值在"之上长出的行业专用 Agent"，不在终端用户数
- Linux 的成功靠发行版把内核变成日用品；**dshed 就是 dsh 的 Ubuntu 位置**
- 目标用户不是"想造 Agent 的开发者"，而是"要问题被解决"的普通人（摄影师、剪辑师、运营、法务…）
- 用户装上 dshed，打开就是可用的专业 Agent，不知道 dsh 存在

**明确的非目标**：
- 不做"又一个 AI 客户端壳"（红海，Claude/ChatGPT Desktop 已占位）
- 不优先做布局/皮肤自定义（低价值，开发者自嗨；dsh 已有主题切换）
- 不做 dsh 引擎的替代或 fork（引擎永远用上游）

## 1. 阶段规划

### v0.2 —— 验证"发行版"假设（当前到下一个里程碑）

**目标**：证明"打开即用专业 Agent"这条链路成立，拿到真实用户反馈。

**交付**：
1. **Agent 包分发机制**（核心技术）：
   - 定义 Agent 包格式（profile 打包：`.dsh-profile`，含配置/插件/图标/说明）
   - dshed 内置「导入 Agent 包」入口（拖拽/文件选择 → 校验 → 安装到 profile 层）
   - 包版本与更新（包内版本号 + 可更新）
2. **官方样板 Agent 包 ×1**：选通用型垂直领域（建议"中文写作/自媒体运营"——用户基数大、无需行业合作即可做出可用包）
3. **官网**：Agent 包下载页（一个包 + 安装说明）
4. **内测验证**：非开发者用户（无 dsh 背景）从官网下载 → 导入 → 完成一个真实任务

**验证指标**：
- 非开发者用户独立完成"下载 → 导入 → 使用"（成功率 ≥ 80%）
- 用户留存意愿（是否愿意装第二个包）

**风险**：Agent 包质量决定口碑；样板包必须"真能用"，不能是玩具。

### v0.3 —— 生态（商店形态）

**目标**：Agent 包从"官方提供"变为"三方供给"，形成目录。

**交付**：
1. 官网 **Agent 包目录页**（列表/搜索/分类/评分）
2. 开发者**上传流程**（表单/校验/预览）
3. 付费包 + 结算（分账：dshed 抽成）——**此阶段才引入支付，且必须解决合规**（国内支付渠道、开发者结算、税务）

**验证指标**：
- 第三方开发者产出包数量（≥ 5 个高质量包）
- 付费包转化率

**风险**：见 §2（MIT 约束）；支付合规成本高，需评估是否自建 vs 第三方平台

### v0.4+ —— 形态

- 布局/皮肤自定义（社区呼声高再做）
- dshed 内嵌包市场（客户端内浏览/安装，不跳官网）
- 企业版（可选）：私有 Agent 包分发、组织管理（届时考虑双许可，见 §2）

## 2. MIT 协议对商业化的约束（关键）

**当前状态**：dshed 代码 MIT 开源。

**约束**：
1. 任何人可 fork/复用/商用 dshed 代码——**"商店抽成"无法靠代码闭源保护**；fork 者可以做一个不带抽成的商店
2. 因此**商业模式必须建立在"代码之外的服务/生态位"**上，而不是代码本身：
   - **品牌与信任**（官方包质量背书）
   - **分发与发现**（目录排名、推荐位、审核）
   - **更新渠道**（包自动更新走 dshed 通道）
   - **开发者生态**（SDK/文档/审核体验）
   - **企业服务**（私有分发、管理后台——可单独收费）
3. 抽成模式的现实形态：**抽成 = 平台服务费**（审核、托管、分发、结算），不是"代码授权费"

**待决策**：
- 商店功能是否闭源（核心体验闭源 + 开源壳）——若闭源商店，建议 v0.3 起步时用 **双许可**（开源核心 MIT + 商店闭源或 PolyForm）
- 若不闭源：接受"商店可被 fork 复制"，靠先发+生态位竞争

## 3. 不做清单（当前阶段）

- 不做皮肤/布局系统（v0.4 再看）
- 不做 dsh 引擎的深度定制（follow 上游）
- 不做多引擎支持（绑定 dsh，单一焦点）
- 不做移动端

## 4. 下一步（1-2 周）

1. **技术调研**：dsh profile 打包格式（一个 Agent 包长什么样、能否独立分发、插件依赖如何打包）
2. **样板 Agent 包**：选领域 → 做配置 → 验证"打开即用"
3. **导入机制**：dshed 内实现 Agent 包导入 UI
4. **与 Codex 评审本文档**（进行中）
